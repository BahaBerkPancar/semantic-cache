# M2: Redis backend and the caching API

GOAL: The same guarded cache behind a real vector store and a small HTTP proxy, with namespaces,
TTL, tag invalidation and a never-cache policy. Still no paid APIs.

SCOPE: `src/scache/` (backend + API), `compose.yaml` (redis-stack only, own project name
`semantic-cache`, bound to 127.0.0.1:6390), `tests/`, README/DECISIONS/CHANGELOG.

RULES: Never read `.env`. Don't touch other repos or containers (pulse-*, t2s*). Ollama only for
embedding new prompts at runtime; tests use a fake embedder and run without Redis by default
(Redis tests marked `redis`, skipped unless `SCACHE_REDIS_URL` is set). Pulling the
`redis/redis-stack-server` image is allowed (pin a tag).

STEPS:
1. **RedisBackend** implementing the M1 backend interface with RedisVL (or redis-py + FT.SEARCH
   KNN if RedisVL adds too much): HNSW or FLAT index, COSINE, dims from the embedder; fields for
   prompt, answer, scope (namespace + user), tags, created_at, ttl; scope filtering inside the
   query (never post-filter after KNN in a way that leaks or starves); TTL via EXPIRE; tag
   invalidation via a tag index. Contract tests run the same suite against InMemory and Redis.
2. **API** (FastAPI, 127.0.0.1:8050): `POST /v1/complete {prompt, namespace, user_id?, tags?,
   ttl?, no_cache?}` → cache lookup (guards) → on miss call the generator (`fake` by default;
   `ollama` qwen2.5:3b optional via setting) → store unless never-cache → response with
   `cache: hit|miss|bypass`, similarity, guard reasons, latency. `POST /v1/invalidate {tag|namespace}`,
   `GET /v1/stats` (hits, misses, bypasses, false-hit reports), `POST /v1/feedback {id, wrong:true}`
   to report a bad hit (evicts the entry and counts it). `/health`.
3. **Never-cache policy**: configurable rules (personal without user id, prompts with dates like
   "today/now", explicit `no_cache`, answers flagged as errors).
4. **Tests**: contract tests for both backends (put/get/scope isolation/TTL/tags/invalidate), API
   tests with the fake generator and in-memory backend, cross-user isolation through the API,
   never-cache rules, feedback eviction. Redis-marked tests run once locally against the compose
   service (start it, run, stop it).
5. Docs: README (run with Docker, curl examples), DECISIONS (RedisVL vs raw, index type, filter
   strategy), CHANGELOG.

DONE WHEN: `uv run pytest && uv run ruff check .` pass without Redis; with
`SCACHE_REDIS_URL=redis://127.0.0.1:6390` the redis-marked tests pass; the compose stack is stopped
afterwards.

ESTIMATE: 90–120 min.

REPORT: report contract. Do not commit, do not push.
