# M3: Traffic replay + showcase

GOAL: Show what the guarded cache does to a realistic stream of requests: cost and latency saved,
and how many wrong answers it would serve, cosine-only vs guarded. Offline and reproducible.

SCOPE: `src/scache/` (traffic generator, replay), `data/traffic*.jsonl`, `bench/replay.*`, `tests/`,
README/DECISIONS/CHANGELOG.

RULES: No paid APIs. Ollama only for `scache embed` of new traffic texts (nomic-embed-text, pulled;
don't pull models); tests use a fake embedder. Replay uses the in-memory backend (Redis optional,
not required). Never read `.env`. Don't touch other repos/containers. Do not commit or push.

STEPS:
1. **Traffic log** `scache traffic` → `data/traffic.jsonl` (fixed seed, ~2,000 requests, synthetic/
   fictional, in the same domain as the pair set but NOT reusing test-split pair texts): each request
   has prompt, namespace, user_id, timestamp, and a hidden `intent_id` (same intent ⇒ same correct
   answer). Mix: exact repeats, paraphrases of earlier intents, near-misses (entity/number/negation/
   time swaps = new intent), personal prompts from several users, time-sensitive prompts, plus a
   long tail of unique prompts; Zipf-like popularity. Document the mix and that it is synthetic.
2. **Embeddings**: extend the embedding cache to the traffic texts (`scache embed`), stale detection.
3. **Replay** `scache replay`: stream requests in time order through `SemanticCache` with the
   threshold chosen in M1 (from `bench/results.json`, not re-tuned on traffic), for cosine-only,
   cosine+guards, and exact-match-only baselines plus no-cache; TTL honoured with the log's clock.
   A hit is "correct" iff the cached entry's intent_id equals the request's. Report: hit rate,
   correct hits, wrong hits served (count, rate per 1,000 requests, by type), personal/cross-user
   leaks (must be 0 for guarded), model calls saved, cost saved (tokens × illustrative price table,
   labelled), latency (measured cache lookup time vs a configurable or recorded generation latency),
   bootstrap CIs over request blocks.
4. Write `bench/replay.{json,md}` and a small SVG (cumulative cost or wrong hits over time);
   `--check` reproduces with tolerance.
5. **Tests**: traffic generator determinism and mix proportions, intent labelling of near-misses,
   replay correctness on a hand-made tiny log (known hits/misses/wrong hits), TTL in replay,
   cross-user leak counter, threshold read from M1 results (not traffic).
6. Docs: README showcase (problem, M1 curve, replay table, what the guards cost/buy, limits:
   synthetic traffic, heuristic guards, intent labels by construction), DECISIONS, CHANGELOG.

DONE WHEN: `uv run pytest && uv run ruff check .` pass offline; embeddings for traffic computed with
local Ollama; `scache replay --check` reproduces `bench/replay.md`.

ESTIMATE: 90–120 min.

REPORT: report contract (CHANGED / EVIDENCE / ESTIMATE vs ACTUAL / NOTES / VERDICT). Do not commit,
do not push.
