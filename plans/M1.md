# M1: Pair set, cache core and the false-hit benchmark

GOAL: Measure, offline and reproducibly, how often a semantic cache would reuse an answer correctly
vs wrongly, and show what guards fix. See plans/ROADMAP.md.

SCOPE: the repo except `plans/`, `AGENTS.md`, `CLAUDE.md`. Replace the template's `items`
model/endpoints/migration/tests; drop Postgres/alembic (not needed). Keep FastAPI for M2 but no
endpoints are required in M1 beyond `/health`.

RULES: No paid APIs; Ollama on 127.0.0.1:11434 (`nomic-embed-text` pulled) only for `scache embed`;
tests never need Ollama. Never read `.env`. Don't touch other repos/containers.

STEPS:
1. **Pair set** `data/pairs.yaml` (≥ 300, all synthetic/fictional): `id`, `a`, `b`, `label`
   (`hit` = same answer acceptable, `miss` = must not reuse), `type`:
   `paraphrase` (hit), `reorder/typo/case` (hit), `entity_swap` (miss: EU↔US, product A↔B),
   `number_change` (miss: 30 vs 60 days, v2 vs v3), `negation` (miss: "can I" vs "can't I"),
   `time_scope` (miss: "today" vs "last year"), `personal` (miss: "my order" queries — must never be
   shared across users), `topic_near` (miss: related but different question). At least 30 per type;
   balanced hit/miss overall. Written without looking at similarity scores; say so in DECISIONS.
2. **Embedding cache** `scache embed` → `data/embeddings.npz` (unique texts, model name, dims,
   content hashes, task prefix `search_query:` for both sides), committed; stale-cache detection.
3. **Cache core** (`scache/cache.py`): `SemanticCache(backend, embedder, threshold, guards,
   scoper)` with `get(prompt, ctx)` / `put(prompt, answer, ctx, tags, ttl)`; `InMemoryBackend` with
   brute-force cosine (numpy) — interface ready for Redis in M2. Context = namespace + optional user
   id; personal prompts are scoped to the user.
4. **Guards** (`scache/guards.py`), each a pure function on (query, cached_prompt) → allow/deny +
   reason: numbers/versions/dates must match exactly; named entities from a small configurable
   gazetteer (regions, product names) must match; negation parity (not/no/never/can't/without…);
   time-scope words must match; personal-pronoun prompts (my/mine/I ordered…) are user-scoped or
   never-cache. Tests per guard with tricky cases (e.g. "v3" vs "version 3" equal; "30-day" vs
   "30 days" equal).
5. **Benchmark** `scache bench`: for thresholds 0.70–0.98 (step 0.01) report, for cosine-only and
   cosine+guards: hit rate on `hit` pairs, false-hit rate on `miss` pairs, overall and per type, with
   bootstrap 95% CIs; pick the threshold on a validation split (fixed seed, 50/50 by pair id hash)
   and report on the test split; write `bench/results.{json,md}` (rounded) and a simple SVG/PNG
   curve (matplotlib allowed as a dev dependency, or hand-written SVG). `--check` compares with a
   tolerance.
6. **Tests**: guards, cosine math, backend put/get/TTL/scoping, threshold selection on validation
   only, metrics vs hand-computed values, bench determinism with a fake embedder.
7. Docs: README (problem, results table and curve, what guards cost in hit rate, limits),
   DECISIONS, CHANGELOG.

DONE WHEN:
- `uv run pytest && uv run ruff check .` pass offline.
- `scache embed` ran against local Ollama; `scache bench` reproduces `bench/results.md`.
- NOTES state honestly what the guards buy and cost.
